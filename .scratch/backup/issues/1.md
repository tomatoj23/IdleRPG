# 规格依据

本规格由 `/grill-with-docs` 会话收敛（33 个决策点），架构依据为 `docs/adr/0001`~`0008`，术语以 `CONTEXT.md` 为准，内容写作规范见 `content/style-guide.md`。

## 三条硬性标准（最高优先级，覆盖本规格全部内容）

1. **引擎与内容完全分离**（ADR-0004）：所有内容（含境界序列、槽位数量等结构性配置）只存在于 `content/`；引擎代码零题材词汇、零写死数量，只能通过内容注册表取配置。
2. **技术选型面向未来，严禁为最小 MVP 采取不考虑未来的保守选择**：修饰符聚合引擎、带完整语境的事件流、版本化存档迁移、Schema 三处同步、`content:check` 硬门禁等基础设施随第一天就做对。MVP 只控制系统数量，不控制架构完备度。
3. **依赖环境项目内自包含**（ADR-0007）：禁止 `npm install -g`、`corepack enable`、修改全局 PATH/shim/配置、升级宿主机 Node；包管理器用 `corepack pnpm`（版本由 `packageManager` 锁定），包缓存在项目内 `.pnpm-store/`；新依赖只进 workspace 的 dependencies/devDependencies。

## Problem Statement

想做一款对标《梅尔沃放置》的放置 RPG，但题材为东方武侠，且玩法核心是《暗黑破坏神》《流放之路》式的装备驱动、多流派构筑。目前项目只有设计文档（`CONTEXT.md`、ADR-0001~0008、agent 约定），需要把已收敛的设计变成一个可玩、可持续扩展的 MVP。

## Solution

构建一个 Monorepo：平台无关的 `core` 游戏引擎（纯 TypeScript）+ React Web 壳 + Schema 驱动的内容编辑器 + 数据化的全部游戏内容 + CloudBase 轻服务端（云存档与单综合排行榜）。核心循环：闭关攒修为 → 采集 → 炼丹 → 突破境界 → 下秘境刷宝 → 分解/洗练强化 Build → 挑战更深秘境。全部内容 JSON + Schema 校验，可视化编辑器与 AI agent 按约定读写同一数据源。

## User Stories

### 玩家

1. As a 玩家, I want 首次进入游戏时创建角色并选择门派, so that 我有一个江湖出身并开始游玩
2. As a 玩家, I want 闭关获得修为且离线也按闭关结算（全额但有上限）, so that 不在线也在变强且有关回归钩子
3. As a 玩家, I want 修为攒满后消耗突破丹等材料进行突破, so that 炼丹与采集循环和境界主轴打通
4. As a 玩家, I want 突破 100% 成功且材料门槛明确, so that 进度可控、无不可控负反馈
5. As a 玩家, I want 在采药场按境界与活动等级解锁的高/中/低阶区域采集 3 阶药材, so that 我能推进炼丹链
6. As a 玩家, I want 通过掉落或门派贡献解锁丹方并炼丹, so that 我有收集与生产目标
7. As a 玩家, I want 服用增益丹获得战斗或闭关效率的临时增益, so that 关键节点有爆发手段
8. As a 玩家, I want 进入秘境自动战斗、招式按冷却自动释放, so that 我放置时也有战斗产出
9. As a 玩家, I want 通关秘境一层解锁下一层且高层更强掉落更好, so that 我有清晰的刷宝目标
10. As a 玩家, I want 战斗死亡仅中断本次探索且不丢失已有掉落, so that 放置体验不被惩罚
11. As a 玩家, I want 掉落装备按底材×稀有度×词缀阶位生成, so that 刷宝有惊喜与追逐欲
12. As a 玩家, I want 穿戴装备并看到角色面板按修饰符规则实时变化, so that 构筑效果可感知
13. As a 玩家, I want 分解不要的装备获得洗练材料, so that 每件掉落都有归宿
14. As a 玩家, I want 用材料洗练单条词缀数值, so that 我能追求极品
15. As a 玩家, I want 用秘籍学习招式与心法并在槽位装配（含先修前置条件）, so that 我能搭配自己的武功组合
16. As a 玩家, I want 词缀与武功通过标签联动（如剑法冷却、毒系伤害）, so that 换一套装备即换一个流派
17. As a 玩家, I want 门派贡献可兑换本派秘籍与丹方, so that 门派身份有玩法价值
18. As a 玩家, I want 门派提供生产类加成, so that 门派选择影响我的成长路线
19. As a 玩家, I want 偶遇奇遇事件的随机叙事文本, so that 放置过程中有翻牌惊喜
20. As a 玩家, I want 战斗画面呈现头像对峙、血条、飘字、招式名弹出与 MUD 式武侠战斗叙事, so that 战斗有武侠味与爽感
21. As a 玩家, I want 同一招式在新手与宗师、暴击与普攻、不同流派下的呈现强度不同, so that 我的构筑成长在画面上被看见
22. As a 玩家, I want 云存档自动同步, so that 我换设备不丢进度
23. As a 玩家, I want 按境界进度+秘境最高层数的综合排行榜, so that 我有比较与竞争目标
24. As a 玩家, I want 零美术资产时看到程序化占位符（按 id 哈希配色+稀有度边框）, so that 游戏在 MVP 阶段依然可玩可读

### 游戏作者（可视化编辑）

25. As a 游戏作者, I want 编辑器根据 JSON Schema 自动生成表单编辑任意内容条目, so that 我不改代码就能调整一切内容
26. As a 游戏作者, I want 表格视图平铺一个集合并支持多选批量调整数值（加减/乘系数/覆盖）与文本批量替换, so that 平衡性调整不用逐条改
27. As a 游戏作者, I want 编辑器的表单与校验由 Schema 驱动、与 core 同源, so that 数据模型永远只有一份
28. As a 游戏作者, I want 编辑器保存时写回 `content/` 的 JSON 文件并能在 git 里看 diff, so that 编辑器与手改文件、agent 修改永不分叉
29. As a 游戏作者, I want 把美术资产按命名约定丢进 `assets/` 即生效（占位符自动被替换）, so that 后期补美术零代码改动

### AI agent（内容批量生产）

30. As a AI 内容作者, I want 按 `docs/agents/content.md` 约定批量新增/改写条目并通过 Schema 校验, so that 我能自动化填充海量内容
31. As a AI 内容作者, I want 批量生产战斗文本模板与按伤害类型分档的后果词库（遵守 style-guide）, so that 战斗叙事持续扩充
32. As a AI 内容作者, I want `npm run content:check` 作为硬门禁且报错必须修复, so that 非法内容无法进入仓库

### 开发者

33. As a 开发者, I want 引擎门面（注入 content/save/clock/rng）作为唯一测试缝合点, so that 全部游戏逻辑可确定性测试
34. As a 开发者, I want 存档为版本化 JSON 快照并带迁移机制, so that 内容与结构演进不毁存档
35. As a 开发者, I want 云存取只走 `SaveStore` 接口（CloudBase 仅是其中一个实现）, so that 后端可替换、UI 壳可插拔
36. As a 开发者, I want 战斗与成长全部以结构化事件流输出（带暴击/伤害类型/伤害占比等完整语境）, so that UI、叙事层、测试、未来模拟器消费同一数据源
37. As a 开发者, I want `core` 包纯 TypeScript 且禁 DOM/平台 API, so that 小程序（Taro）与桌面（Tauri）移植只换壳

## Implementation Decisions

- **Monorepo 布局**：`packages/core`（引擎，纯 TS，禁 DOM）+ `apps/web`（React+Vite 壳）+ `apps/editor`（Schema 驱动的本地编辑器，dev server 提供内容文件读写 API）+ `content/`（全部内容）+ `schemas/`（与 content 集合一一对应的 JSON Schema）+ `assets/`（美术，约定路径）
- **引擎门面**：`createGame({ content, save, clock, rng })` 返回命令 API、查询 API、事件流。唯一测试缝合点。内容必须先过 Schema 校验才可进入
- **进度**：境界制（config 驱动的序列，MVP 六境界：不入流→三流→二流→一流→绝顶→宗师）；修为只来自闭关；突破 = 修为满 + 材料门槛（含突破丹），100% 成功；闭关离线全额结算、有上限（config）
- **门派**：数量由内容目录决定（MVP 3 个：华山/丐帮/唐门），决定可学武功池与生产加成；门派贡献兑换；MVP 不可换派；门派条目含 `masters`（师父）字段承载可教武功池与教学规则
- **武功**：招式（主动，冷却释放）+ 心法（被动）；装配槽 4+3（config）；**品阶 下乘/中乘/上乘/绝学**（config）；带标签（剑法/掌法/毒系…），标签枚举在 config；含**前置**（先修武功与等级要求）
- **装备**：底材（带固有词缀）× **稀有度（寻常 0/精良 1~2/罕见 3~4/绝世 5~6 含特色词缀）** × 词缀阶位 T1~T3；掉落等级由秘境层数决定；6 槽位（config）；socket 字段位预留
- **数值**：修饰符聚合引擎（固定值 → 加法百分比 → 乘法区三层），词缀/心法/增益丹统一产出修饰符，禁止绕过修饰符直改属性；境界提供基础数值与门槛
- **装备循环**：掉落 → 穿戴 + 分解 → 洗练（重随单条词缀数值）；完整 craft 留后续
- **战斗**：纯数值模拟，输出结构化事件流（含完整语境：**伤害类型**割/刺/瘀/内伤/抓伤、是否暴击、伤害占比、来源标志）；死亡仅中断
- **呈现**：双层——视觉层（头像对峙/血条/飘字/招式名弹出，强度随事件语境映射）+ 叙事层（MUD 式模板引擎，模板与后果词库**按伤害类型分池**、为内容，频率受控）；两层均在 UI 侧，完全内容驱动；视觉基准见 `docs/design/ui-direction.md`
- **内容管线**：条目一文件；`content/config/` 存结构性配置（境界、曲线、槽位、阈值、配色表、**显示档位**）；id 一经发布不可变；`npm run content:check` 为提交硬门禁；Schema 变更需同步 core 校验器、编辑器表单、`docs/agents/content.md`
- **生产活动**：采集与炼丹等活动含**等级**（`level`/`xp`），与境界门槛共同决定可进入的采集区
- **内容归属**：条目用 `sectId`/`regionId` 表达门派/区域归属，校验器检查覆盖与连通；不做目录分层
- **显示档位**：由数值推导的造诣描述（不堪一击→初窥门径→稍有所成→登堂入室→炉火纯青→出神入化→返璞归真），config 配置，供战斗文本与界面使用
- **资产**：约定路径 `assets/{icons|portraits}/<集合>/<id>.png`，JSON `art` 字段可覆盖；无资产时程序化占位符（id 哈希配色 + **稀有度边框**）
- **后端**：CloudBase（云函数 + 云数据库）；`SaveStore` 接口抽象（Web SDK / wx SDK / HTTP 三种适配）；存档为版本化 JSON 快照 + 迁移机制；服务端不解读业务逻辑；**CloudBase SDK 只进 workspace 依赖，禁全局安装（ADR-0007）**
- **排行榜**：单综合榜（境界进度 + 秘境最高层数的综合分，公式在 config）
- **MVP 内容盘子**：3 门派 × 8~10 武功；词缀池 20+ 条 × 3 阶；3 秘境 × 10 层；药材 9 种（3 区 × 3 阶）；丹方 6 张（2 突破丹 + 4 增益丹）；奇遇 20 条；combat-text 模板与词库初版
- **数值曲线**：每境界闭关时长 2~3 倍递增，首个境界 30 分钟内可首破

## Testing Decisions

- **唯一缝合点**：引擎门面。所有测试通过 `createGame` 的命令/查询/事件流断言外部行为，禁止测试内部实现细节
- **确定性**：clock 与 rng 从构造注入——测试用固定种子随机源、可拨动的假时钟（离线结算、冷却、增益时长全部可精确断言）
- **假实现**：`SaveStore` 用内存实现；CloudBase 不进单元测试
- **内容管线测试**：合法/非法内容样例集，覆盖 `content:check` 的通过与拦截路径；id 不可变规则的破坏性用例
- **先例**：greenfield 无既有测试，从第一切片起以 `/tdd` 建立（红→绿→重构），测试文件组织随 `core` 包结构
- **UI 侧**：不做逻辑测试；模板引擎（事件→文本）属于可测范围，仍通过内容注入测渲染选择逻辑

## Out of Scope

- 走火入魔（突破失败惩罚）
- 换派 / 叛师 / 跨派偷师
- 完整 POE 式工艺台（词缀重铸、底材打造、稀有度洗练）
- 武器 socket（仅预留数据字段位）
- 横版小人渲染、真实美术资产
- 微信小程序 / Steam 桌面端发布（架构预留，不实现）
- 多个排行榜、公会/联机玩法、交易系统
- 文风包（白描/古龙/金庸风）作为可切换内容包
- 移动端适配打磨
- **任务体系**（任务发布人、任务四元组、任务道具均不设 schema，形态未定）
- **知识 / 生活技能**（读书、医术等；生产活动等级只服务采集与炼丹）
- **独立 NPC 集合**（师父归入门派条目字段，其余 NPC 类型不做）
