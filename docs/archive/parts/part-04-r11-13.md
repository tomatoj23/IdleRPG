## 十一、Round 11：宠物/召唤物的调研与立场

### 11.1 调研结果（先查资料再表态，不凭印象）

**支持"动物能进武侠"的证据**：
1. **xkx100 有 `clone/animal/` 品类，34 个文件**（`xkx100-content-structure.md:117`：`clone/` 按品类分目录 weapon(183)/cloth(134)/book(155)/medicine(122)/food(155)/armor(31)/jewelry(19)/**animal(34)**/gift(45)/money/flower/misc）。金庸题材 MUD 把"动物"列为与兵器、衣物并列的大品类——动物在武侠内容模型里有位置。
2. **金庸有"驭兽作战"的硬先例**：小龙女的**玉蜂**（《神雕侠侣》中直接用于攻击）、欧阳锋的**蛇阵**（白驼山）。不是边缘设定，是正典。
3. 随行伙伴亦有先例：杨过的神雕、郭靖的双雕。

**反对"召唤"的证据**：
1. **`ui-direction.md:9` 白纸黑字禁了符箓**："清新淡雅水墨……**武侠而非仙侠**（禁飞剑、金光、**符箓**、云海仙境、渡劫雷电）"。用户举的"道家符箓"这一支，**在我们自己的视觉基准文档里已被明确排除**。
2. **"凭空召唤"在武侠里没有对应物**。撒豆成兵、纸人替身、召雷役鬼属志怪/仙侠谱系，与 `style-guide.md:22` 禁的修仙词（金丹、元婴、灵气、渡劫、飞升）是同一条边界。
3. **青城派**：金庸《笑傲江湖》确有青城派（余沧海、松风观），青城山确是道教名山，但**金庸笔下的青城派是剑派不是符箓派**——没有"青城 = 符箓"的支撑。

### 11.2 立场：同意「驭兽」，反对「召唤」

区别在本体论层面，不是措辞：

| 形态 | 本体 | 武侠成立吗 |
|---|---|---|
| **驭兽** | 真实存在的动物，被驯养/驱使 | ✅ 小龙女玉蜂、欧阳锋蛇阵 |
| **机关傀儡** | 人造器械，墨家/公输班一脉 | ⚠️ 有先例但边缘，需新势力（门派）支撑 |
| **召唤物** | 凭空生成的单位（符箓、撒豆成兵、式神） | ❌ 仙侠谱系，且 `ui-direction.md:9` 已禁符箓 |

**推荐路线：驭兽**。机关傀儡作第二条线留待门派设计时评估。

### 11.3 与七系的「有逻辑关联」：兽是机制放大器，不是伤害复制品

用户明确要求"不是单纯把七系效果复制到召唤物上"。方案：**兽不造成该系伤害，它改造该系机制的行为方式**。

| 系 | 兽 | 它做的事（放大机制，而非复制伤害） |
|---|---|---|
| 木（疫毒·传染） | 毒蜂／蛊虫 | 把单体中毒**扩散**到邻近目标——把"传染"从概率变成必然 |
| 火（燃爆·灼烧） | 火鸦 | **引爆**灼烧——提前结算目标身上剩余的灼烧层数 |
| 水（滞缓·冰寒） | 寒蟾 | **延长**目标身上的迟缓持续时间 |
| 金（破防·裂伤） | 铁啄鹰 | **维持**破甲状态不衰减（本来会随时间恢复） |
| 土（守护·护体） | 石龟 | **转移**伤害——替主角承受一部分，而非自己加护甲 |
| 风（迅疾·提频） | 灵隼 | **缩短**主角招式冷却，而非自己打得更快 |
| 雷（霆爆·暴击） | 雷兽 | 主角暴击时**追加**一次雷击，而非自己暴击 |

关键：每一个都是"**改变主角已有机制的某个参数**"。兽与七系的关联是机制层面的因果，不是"颜色相同"。构筑深度来自"选哪只兽 = 强化自己主机制的哪个方面"。

### 11.4 兽 = 本轮最大的引擎坑

战斗从 **1v1 变成 NvM** 牵动：事件流（谁打谁、参与者身份标记）、权重轮盘（各自轮盘还是统一调度）、内力（兽消耗谁的内力）、闪避/防御（兽是否有自己的属性）、战斗文本（`{attacker}` 可能是"你的灵狐"）、存档、UI、平衡、内容量。

**结论分两半**：① 引擎必须把"战斗参与者"建模成集合而非两个固定角色（成本 ≈ 0，已入 A.10 第 5 条）；② 功能是否进 MVP 是独立决策。

### 11.5 用户决策 + 一次沟通错位（重要，记录以免重犯）

- **Q33 = 接受推荐**：驭兽
- **Q34 = 用户答"兽进 MVP"** —— 但 Q34 原本问的是"**参与者集合抽象现在做不做**"，用户理解成了"兽进不进 MVP"。**助手未指出错位，直接按"兽进 MVP"往下处理**，导致用户困惑："你不是说成本约等于零吗？"

**成本对照（澄清后）**：

| 事项 | 成本 |
|---|---|
| "参与者集合"引擎抽象（Q34 本意） | **≈ 0**，且无论兽进不进 MVP 都要做 |
| 兽进 MVP · 2 只 | ≈ 现有 MVP 的 **15%** |
| 兽进 MVP · 7 只 | ≈ 现有 MVP 的 **30-50%** |

## 十二、Round 12：闪避文本、兽文本、Q34 重述

### 12.1 Q34 重述（给用户重新决策的机会）

已在上表澄清。用户最终选择：**Q37 = 2 只兽**（见下），即选项 A。

### 12.2 闪避文本：独立模板族（Q38）

现有模板套不上闪避（它有 `{limb}` 和 `{consequence}`，而闪避两者都没有）。**闪避需要自己的一套片段**：

```
{dodgeSubject}{dodgeManner}，{dodgeMove}避过{attacker}的「{move}」{dodgeAftermath}。
```

| 片段 | 说明 | 选择依据 |
|---|---|---|
| `{dodgeSubject}` | 闪避方（**在闪避文本里是主语**） | 即 `{defender}` |
| `{dodgeManner}` | 闪避姿态：气定神闲，笼袖不动／足下生风／仓促侧身／勉强向旁一滚 | **剩余生命档 × 是否有身法 × 实力差** |
| `{dodgeMove}` | 身法招式名（凌波微步、屏翳收风），可为空 | 该角色是否有轻功类武功 |
| `{dodgeAftermath}` | 擦身而过的痕迹："剑锋擦着颈侧掠过，削落一缕鬓发" | **险胜档**专用 |

**三条示例**：
> **从容·有身法**：黑衣人足下生风，一式「凌波微步」飘然避过你的「白虹贯日」。
> **狼狈·残血·无身法**：黑衣人脚步踉跄，勉力向旁一滚，堪堪避开这一剑。
> **险胜**：黑衣人仓促侧身，剑锋擦着颈侧掠过，削落一缕鬓发。

**「险胜」档性价比最高**：让"闪避成功"有了强弱之分，且**不需要任何新字段**——闪避判定值与阈值的差距本身就是现成数据，内容层按差距分档即可。

**兑现既有承诺**：`research:266` 已要求"为「闪避」「格挡」各设基本模板组"，`style-guide.md:32` 已写"暴击/闪避/反伤/中毒 各有专属模板池"——这不是新增需求，是兑现已承诺未兑现的条目。

### 12.3 Q38 补充（用户追加）：闪避文本受「实力差」门控

用户原话："总不能大师险胜新手吧。"

➡️ 闪避文本性质必须反映双方实力关系。落在现成的**显示档位**上（`CONTEXT.md:83` 七档：不堪一击→…→返璞归真，由数值推导）：

| 实力关系（双方显示档位之差） | 闪避成功的叙事性质 | 示例 |
|---|---|---|
| 攻击方远高于防守方 | **侥幸**——弱者居然躲开了 | 你仓促侧身，剑锋擦着颈侧掠过，削落一缕鬓发。这等险象，连你自己都愣了一瞬。 |
| 双方接近 | **正常**——一来一回 | 黑衣人足下生风，一式「凌波微步」飘然避过你的「白虹贯日」。 |
| 防守方远高于攻击方 | **从容**——理所当然 | 黑衣人笼袖不动，只微微一侧身，你这一剑便落了空。 |

**大师对新手**：大师闪避 → 从容档；新手闪避 → 侥幸档。绝不会出现新手"气定神闲"地躲开大师。

**随机性保留在档位内部**：逻辑管"该进哪个池"，随机管"池里选哪条"（每档 3-5 条候选）。

**事件流补充**：**双方显示档位**（离散七档）需与剩余生命档一起进事件流（见 A.9）。

### 12.4 兽文本（Q39）

**触发条件：兽出场 = 它正在执行它的机制**（解决逻辑性——不是随机乱入）

| 兽 | 触发时机 |
|---|---|
| 毒蜂（木） | 目标中毒层数达阈值，毒蜂正在扩散 |
| 火鸦（火） | 灼烧被引爆的那一刻 |
| 寒蟾（水） | 迟缓被延长时 |
| 铁啄鹰（金） | 破甲状态被维持住时 |
| 石龟（土） | 它替主角承受了伤害 |
| 灵隼（风） | 招式冷却被缩短时 |
| 雷兽（雷） | 暴击追加雷击时 |

**频率节流**：条件满足时按概率出场（config 可调，如 25%）+ 出场冷却（如 3 回合内不重复）→ "不用每招都露脸，但时不时刷存在感"。

**品阶差异 = 片段数，不是频率**（与招式模板的可变长度同一套规则）：

| 品阶 | 片段数 | 示例 |
|---|---|---|
| 下乘 | 1 段 | 毒蜂嗡然散开，毒雾漫向一旁。 |
| 中乘 | 2 段 | 你肩头毒蜂骤然振翅，嗡然散开，毒雾顺着剑风向旁边那名敌人漫去。 |
| 绝学 | 3-4 段 | 你肩头那只异种毒蜂清唳般振翅而起，翅上金纹在火光下骤然一亮——它绕着黑衣人的伤口盘旋半匝，尾针连点，将那处青紫的毒气生生逼向了旁边同伴的脉络。 |

**与主人的互动：四种类型**

| 类型 | 触发 | 示例 |
|---|---|---|
| 救援 | 主人受到致命档伤害 | 石龟横过身来，替你硬受了这一记——壳上裂开一道细纹。 |
| 配合 | 主人出招时同步行动 | 你一剑递出，灵隼自肩头掠下，双爪抓向对方双目。 |
| **反馈** | 主人血量档变化 | 灵隼低鸣盘旋，似在催促你退开。 |
| 增益 | 兽为主人提供加成 | 石龟昂首，一层土黄色的光晕自你周身浮起。 |

**"反馈"型最有价值**：与 `{opening}` 的残血词库天然联动——主人残血时 `{opening}` 说"虽已浑身是血，仍作殊死一搏"，兽的反馈紧随其后，两句构成叙事呼应。用已有字段白捡的戏剧性。

**架构要求（很轻）**：兽文本是**可选插入片段**，不是主模板一部分。只需要 ① 事件流能标记"这只兽的机制触发了"；② 文本组合器支持"主模板 + 可选插入"。**都不需要新架构**。

**并发处理**：同一回合可能同时触发"兽出场"和"致命一击"（如石龟替你挡下致命伤）。需要**片段优先级**——建议**兽片段插在主文本之前**（因果上先发生）。

## 十三、Round 13：兽的引擎预留 + 门派山头 + 变强反馈

### 13.1 用户确认：兽 = 装备（采纳，推翻助手原方案）

用户原话："兽本身不参与攻击，本质上就是一件装备，区别是这个装备会在文本描述处有一席之地。"

**助手验证结果：用户是对的。** 逐个检查 7 只兽的效果能否表达为"对主人已有机制的修饰"：

| 兽 | 效果 | 能否表达为修饰符 | 用哪个维度 |
|---|---|---|---|
| 毒蜂（木） | 扩散中毒 | ✅ | `targetSelector`（单体 → 多个） |
| 火鸦（火） | 引爆灼烧 | ✅ | trigger + `condition`（提前结算 DoT 剩余层） |
| 寒蟾（水） | 延长迟缓 | ✅ | `duration` |
| 铁啄鹰（金） | 维持破甲 | ✅ | `duration`（不衰减） |
| 石龟（土） | 转移伤害 | ✅ | `stat-modifier` 减伤 + 叙事包装 |
| 灵隼（风） | 缩短冷却 | ✅ | `rate-modifier` |
| 雷兽（雷） | 暴击追加 | ✅ | `condition: on-crit` + `instant-damage` |

**七个全部通过**，且用到的维度恰好就是 Round 3 定的四个通用参数 `amount / duration / targetSelector / condition`——因为"修饰"的本质就是改这几个维度。

**证据链**：① 七效果全可表达为修饰符 → 兽不需独立回合/属性/事件；② 战斗**保持 1v1**，不需 NvM；③ 引擎**零新增概念**（它不需要知道"兽"，只知道"带修饰符 + 叙事片段的装备条目"）；④ 直接兑现 `ADR-0004`。

**未想到的额外收益：这个能力可推广。** "装备可以提供叙事片段"是通用能力，于是兵器 → `{weaponAction}`、兽 → 兽片段、名剑「流云剑」→ "剑身发出一声清鸣"，**三者是同一类东西**。兽不需要任何专属文本机制，只复用"装备声明 narrative 片段"这个能力。

**成本重估**：

| | 助手原估（NvM 模型） | 装备模型 |
|---|---|---|
| 战斗模型 | NvM（需参与者集合） | **1v1（不变）** |
| 兽的属性/血量/AI/成为目标 | 需要 | **不需要** |
| 新增工作量 | ≈15% | **≈5%** |

**边界（诚实告知）**：兽不能 ① 成为敌人攻击目标；② 有血量、会死；③ 在主人不出招时独立行动。石龟"替你挡下"在装备模型下是**减伤修饰符 + 叙事包装**（实际是伤害减少，叙事上说是石龟挡的），玩家看不出但设计时要知道。

**"参与者集合"抽象仍然要做（≈0 成本）**：现在兽是装备用不上它，但将来兽升级成真单位（能被打、能死、能独立行动）时不用重写战斗系统。**不矛盾**——兽=装备是内容决策，参与者集合是形状。

**槽位**：兽走**独立"随从"栏**，不占 6 个装备槽（兵/冠/甲/腕/腰/靴）。理由：兽不是穿戴物，独立栏 UI 清晰，将来升级为单位时栏位模型仍成立。

### 13.2 兽的关键能力（挡濒死）需要引擎预留

用户追问：关键能力需概率 / CD 限制，是否要在引擎层面完善或预留？

| 需求 | 引擎要什么 | 是不是坑 |
|---|---|---|
| 致命判定 | 伤害管线中"应用伤害之前"的**拦截点**，能判断"这一击会不会致死" | 是形状问题，现在定便宜 |
| 概率触发 | primitive 支持 `chance` 参数 | 不是坑（参数而已） |
| **冷却** | 效果实例要**带 CD 状态**，且这是**运行时数据，要进存档** | **真坑** |

➡️ 要预留的是：**效果实例 = { 定义 + 运行时状态（剩余冷却、已触发次数、剩余层数……）}**，运行时状态是存档的一部分。**现在就要进设计，即使 MVP 一只带 CD 的兽都不做。**

**更深的坑：概率触发在离线结算时怎么办？**
闪避可用期望值（影响 DPS，连续）；但**致命保护是 0/1 事件**，决定角色死不死，期望值会失真（不能说"平均死了 30%"）。三个解法：

- **A. 离线战斗不致死**：离线秘境推进不会让角色死亡，最多"推不动了"；致命保护离线时不参与计算。
- **B. 保守模型**：离线假设保护未触发，若致死则判定推进失败。安全但偏严。
- **C. 离线按 CD 就绪与否确定性判断**：不掷骰，CD 好了就算触发。可预测但在线/离线规则不一致。

➡️ **推荐 A**：放置游戏的离线结算本就该是"稳的"，让死亡成为离线结果会让玩家不敢离线，与放置品类核心体验冲突；在线时该机制照常掷骰，严肃性未丢。

### 13.3 activation 字段

**解释**（用户追问该字段是什么）：招式的**释放方式**——`auto`（按冷却 + 权重轮盘，当前唯一形态）／`manual`（玩家点按钮）。

**决策**：现在不加（避免为不确定功能预留数据字段），但**引擎层 intent 源可插拔现在就做**；将来加字段的成本由 ADR-0002 版本化存档迁移兜底。**不锁死后期扩展**（用户明确要求）。

### 13.4 代价数值后置

用户："代价数值也随便选，重要的是先把机制写好，或者不限制未来调整机制的空间。"

**保证**：所有代价参数在 config，调整数值不改引擎；**连机制本身也能扩展**（新的代价形式 = 新的 primitive 组合或新的 condition）。现在写下的任何数字都不是承诺，只是初值。

### 13.5 门派内部「山头/派系」：同意做分化，反对做成互斥专精

**用户设计**：每个门派内部有不同"山头"（长老主张不同）→ 不同武学主张 → 对应七系（如丐帮是火系，但某性情温和的长老传下木系/水系武功）。担忧：形成 WoW"职业 + 专精"模式。

**这不是 WoW 模式，是武侠正典**（证据）：
- **华山派剑宗 / 气宗之争**——《笑傲江湖》整部书的骨架。同门之内，一派主"以剑招为先"，一派主"以气御剑"，斗到你死我活。
- **丐帮污衣堂 / 净衣堂**——《射雕英雄传》。同一帮派，一派破衣烂衫守旧制，一派衣冠齐整求变通。

两条证明：门派内部有主张分歧是武侠的**原生结构**，不是从 WoW 借来的。WoW 的"专精"也是从这类叙事传统长出来的，源头在武侠这边。

**但"专精"有一个陷阱**：WoW 专精是**互斥**的。若山头也做成"必须选一个、只能学该山头武功"，则硬冲突 `ADR-0001`"**流派由玩家玩出来，不预设标签**"。

**立场：山头是武功池的细分标签，不是玩家的身份选择。**

| | 山头（建议） | 专精（要避免） |
|---|---|---|
| 它是什么 | 武功池的**归类标签** | 玩家的**身份选择** |
| 能否同时拥有多个 | **能**（受贡献/前置限制） | 不能（互斥） |
| 谁来"选" | 玩家通过**装配**选（招式 4 / 心法 3 槽位限制） | 系统让玩家在进入时选死 |

结果：丐帮既有火系「降龙十八掌」也有某长老的木系/水系武功，玩家**两个都能学**，但槽位有限 → "专精感"由槽位逼出来，不是系统规定。完全兑现 `ADR-0001`。

**实现很轻**：`content.md:42` 已有 `sectId`，山头只需并行字段 `factionId`，校验器照 `sectId` 那套做覆盖与连通检查。引擎不认识"山头"——它只是与门派、区域同级的归属标签。

**命名**（用户说"长老只是举例"）：武侠里真实存在的有**脉、支、堂、院**。"堂"最贴（污衣堂/净衣堂），"脉"最简洁（剑宗气宗说两脉）。建议按门派气质选。

### 13.6 门派"要精"：区别落在战斗节奏而非颜色

3 个门派要鲜明区别，建议用**节奏差异**而非系别差异：

| 门派 | 缺省系 | 节奏 | 内力特性 |
|---|---|---|---|
| 丐帮 | 火 / 雷 | **爆发型**：短时间倾泻，之后疲软 | 高消耗、高回复需求 |
| 武当 | 水 / 土 | **持久型**：防守反击，拖得住 | 低消耗、续航强 |
| 唐门 | 木 / 金 | **累积型**：毒/破甲叠加，越打越疼 | 中等消耗、前置投入长 |

同样"变强"：丐帮感到"一下更疼了"，武当"站得更久了"，唐门"叠得更快了"。比"三个颜色不同的火球"鲜明，且不需额外系统（缺省系别 + 武功池 + 内力参数即可实现）。

### 13.7 变强反馈：档位缺一个「中频刻度」

用户问题："档位变化其实是比较慢的，但是玩家需要提升时的反馈，有没有其他办法增加变强的反馈？"

**诊断**：现有反馈两头重、中间空——

| 频率 | 现有反馈 | 状态 |
|---|---|---|
| 慢（天/周） | 境界突破（6 档）、显示档位（7 档） | 有，但太慢 |
| **中（小时）** | **——** | **空的** |
| 快（分/秒） | 伤害数字、暴击、掉落 | 有 |

玩家 90% 时间活在中高频，那里基本空白。四个补法（按性价比排序）：

**A. 战力 / DPS 指标（最该做）**
由全部属性聚合的连续数值，每换装备/每提升境界都会动，把慢反馈转为连续反馈。与显示档位**互补而非重复**：显示档位 = 离散的、叙事化的（"炉火纯青"）给身份感；战力 = 连续的、数值化的（12,345 → 12,890）给进度感。**档位之所以显得慢，正是因为它底下没有一条连续曲线托着它**。顺带补一个旧账：审计发现"战力"在 `CONTEXT.md` 零出现（`ui-direction.md:189` 用过一次），需正式词条。

**B. 秘境推进记录**
"已推进至第 18 层（历史最佳 15 层）"。秘境分层是已有设计（`CONTEXT.md:53`），加最高层记录几乎零成本，给玩家每次刷新都能看到的里程碑。

**C. 战斗内「新纪录」提示**
"最高伤害 3,847！"存几个 max 值 + 文本提示，换高频惊喜感。

**D. 叙事化的变强反馈（免费，最贴我们的设计）**
**战斗文本分档系统本身就是一台变强反馈机。** 同一招打同一敌人：弱时"剑锋掠过，衣袖裂开一道口子，血线缓缓渗出"→ 强了"剑锋及体，皮肉焦黑，一股焦臭随之腾起"→ 更强"一剑斩落，黑衣人连人带剑被劈作两段"。**文本自己会告诉玩家"你变强了"**，且是最有体感的方式。伤害档、剩余生命档、系别、品阶这些分档维度已全定，这条反馈**现成、零额外成本**。且 `style-guide.md:24` 已要求避免"数值直出的干瘪句"——所以"造成 100 点伤害 → 120 点伤害"本就不该是我们的反馈方式，**"伤口从血线变成焦黑"才是**。
