## 二十二、Round 22：#3 秘境结构（二）——定时波次深化 + 手动目标选择

### 22.1 定时波次的价值：难度是涌现的，不是配出来的

| | 清完才来下一波 | 到时间就来 |
|---|---|---|
| 本质 | 流程控制 | **压力检验**（清怪速度 vs 生成速度） |
| 难度来源 | 手工调怪物强度 | **自动生成**（两个速度的比值） |
| 玩家感受 | 一段一段的关卡 | 连续的张力曲线 |
| DPS 不足时 | 卡在某一波（硬墙） | **怪物逐渐堆积 → 吃紧 → 崩盘（连续反馈）** |

关键优势：DPS 略低于阈值时，玩家经历"轻松 → 吃紧 → 危险 → 崩盘"的连续曲线，能感知"差一点就撑住了"——这正是放置游戏最想要的"再变强一点就能过"。**比"第 N 层打不过"这种硬墙反馈多得多。**

### 22.2 模型（含用户 Round 22 追加的提前规则）

**用户追加**："如果这波打完了但没到时间，则提前来。"

```
触发下一波的条件 = 时间到  OR  上一波已清空     ← 取较早者
```

即"清完才来"与"定时才来"的**并集**。好处：不浪费时间（清完立即来），压力不中断；同时保留了"清不完就堆积"的压力源。

```
进入第 N 层
  ├─ t=0        生成第 1 波
  ├─ t=T1 或 第1波清空（取先到）→ 生成第 2 波
  ├─ ...
  ├─ 第 K 波生成完毕（K = 本层波数）
  └─ 场上清空 且 波次已全部生成 → 通关本层
```

**四个参数**（全部进 `content/config/`，后台可改）：

| 参数 | 说明 |
|---|---|
| `waveCount` | 本层几波 |
| `waveInterval` | 波间隔（固定值／区间随机／逐波递减） |
| `waveComposition` | 每波什么怪（固定表／从池随机） |
| `maxConcurrent` | 场上怪物上限 |

### 22.3 三个定案细节

**1. 场上怪物上限 = 技术护栏，不是难度调节**
无上限会导致无限堆积（性能隐患 + 新手一进场就淹没）。建议设 12–20 的**技术性上限**，超出的波次**延后**而非丢弃。玩法上仍是"堆积→压力"，技术上不失控。

**2. 随机化两层，但可控**
- 间隔随机：`T ± 20%`（保留节奏感，不至于变运气）
- 构成随机：从本层怪物池抽，但**保底构成固定**（如"每波至少 1 个小兵"）
- 精英/Boss 波**不放进随机池**，固定在指定波次

**核心原则：随机性放在"节奏与搭配"上，不放在"难度"上**——难度必须可预期，否则玩家的变强感知会被运气污染。

**3. 这用上了为兽预留、一度看似白做的抽象**
Round 11 定的"**战斗参与者建模为集合**"（A.10 第 5 条），后因兽按装备模型实现而一度无用武之地。**现在定时波次用上了**——场上同时存在 N 个怪物实体，各有血条、状态、目标选择。
→ 值得记住的教训：**形状抽象的成本是零，但价值要等某个功能出现时才兑现**。当时保留它是对的。

### 22.4 手动目标选择（用户提出，Q48 同理）

**用户原话**："建议加上手动选择，因为**如果一个技能的属性是随机单体目标，但本层需要先秒掉某个关键怪，怎么办**？"

这是一个真实的战术需求：**随机单体 + 需要先杀关键怪 = 玩家失控**。

➡️ 解法落在 Round 13 已定的 **intent 模型**上，而且发现 intent 的三个维度可以**独立配置来源**：

```
intent = {
  actor:   谁释放    ← auto
  skill:   用什么招  ← auto（权重轮盘）| manual（玩家点招式）
  target:  对谁      ← auto（targetSelector）| manual（玩家点目标）
}
```

于是三种形态自然浮现，不需要新增机制：

| 形态 | skill | target | 说明 |
|---|---|---|---|
| 纯自动 | auto | auto | 当前默认 |
| **半自动**（用户要的） | **auto** | **manual** | 系统出招，玩家指定打谁 |
| 全自动 | manual | manual | 玩家点招式 + 点目标 |

**重要**：这说明 Round 13 的"intent 源可插拔"不只支持"手动放招"，还支持"手动选目标"——**因为三个维度可独立配置**。这是对 Round 13 抽象的一次正向验证。

**⚠️ 由此引出一个必须解决的矛盾**：**离线时没有玩家输入**，target 只能走 auto。若某层需要先集火关键怪，离线就推不过去。

➡️ **推荐解法：玩家配置"目标优先级策略"**（如"优先精英"／"优先残血"／"优先最高威胁"）。离线时按此策略选目标，玩家的战术意图被保留，离线推进不受影响。这是**策略配置**而非实时操作，符合放置品类。

**引擎要求**：`targetSelector` 需支持两类来源——① 招式自带（内容声明）；② 玩家策略配置（存档）；③ 实时玩家点击（仅在线）。三者优先级：③ > ② > ①。

### 22.5 用户确认（Q49–Q51 按推荐）

- **Q49 = 波间隔与构成的随机化**：间隔 `T ± 20%`；构成本层池随机 + 保底固定；精英/Boss 不进随机池
- **Q50 = 每 N 层一个层主**（如第 5、10 层），非每层都有。理由：每层有 Boss 会让 Boss 贬值且拖节奏；每 N 层给里程碑感，与 A.13 的"秘境推进记录"呼应
- **Q51 = 混合解锁**：前几个链式引导（新手），之后按推荐境界并列开放。符合 `ui-direction.md:44` 的"**渐进化解锁 UI**"（元素随进度逐步出现，初期极简，避免一次性淹没）

## 二十三、Round 23：#1 装备底材与词缀池

### 23.1 现有依据

`ADR-0005`：底材（每槽位多类，带固有词缀）× 稀有度（寻常 0 / 精良 1~2 / 罕见 3~4 / 绝世 5~6 含特色词缀）× 词缀阶位（T1~T3，高阶仅高层数秘境掉落）。**掉落等级由秘境层数决定**。词缀池 MVP 20+ 条 × 3 阶。流派来源是**词缀标签 × 武功标签联动**。装备循环：掉落 → 穿戴 / 分解 / 洗练。

### 23.2 掉落生成的完整链条（七次随机）

```
击杀
 ├─ ① 掉不掉（roll）
 ├─ ② 掉落等级 = f(秘境层数)
 ├─ ③ 选底材（从该等级可用的底材池）
 ├─ ④ 掷稀有度              ← 因
 ├─ ⑤ 按稀有度定词缀条数      ← 果
 ├─ ⑥ 抽词缀（受底材倾向权重影响）
 ├─ ⑦ 每条词缀掷阶位（受掉落等级限制）
 ├─ ⑧ 每条词缀掷数值（在该阶位区间内）
 └─ ⑨ 附加底材的固有词缀（固定，非随机）
```

⚠️ **引擎要求：这条链必须是可配置管线，不是写死的代码**——否则将来想改任一步（如"稀有度也受层数影响"）都要动引擎。

### 23.3 底材 = 物品等级方案（Q52）—— ⚠️ **Round 24 已修正为「底材分层」，本节的 itemLevel 方案降级为可选**

> **修正说明**：本节推荐的"一个底材条目 + `itemLevel` 整数"只解决了数值区分，**没解决文本与美术的区分**。用户 Round 24 指出高层应掉落**另一个底材**（换名字、换描述、换美术），品阶范围也随之提高。**以 Round 24.1 为准。**

（以下保留原方案内容备查）

**底材条目只有一个，掉落时附一个整数 `itemLevel`**：

```json
{
  "id": "base-xuantie-sword",
  "name": "玄铁剑",
  "slot": "weapon",
  "implicitAffix": "affix-heavy",
  "preferredTags": ["力量", "破甲"],
  "itemLevelRange": { "min": 10, "max": 100 }
}
```

同一把剑在不同层的表现：

| 掉落位置 | itemLevel | 可出阶位 | 数值系数 |
|---|---|---|---|
| 第 3 层 | 3 | T1 | ×1.0 |
| 第 30 层 | 30 | T1–T2 | ×1.6 |
| 第 80 层 | 80 | T1–T3 | ×2.8 |

**三方案对比**：
- A（无等级）：第 3 层与第 80 层的剑完全一样 → 高层掉落无优势，玩家无刷高层动机
- B（等级变体）：需建「玄铁剑·凡/精/绝」三个独立条目 → 内容量 ×3，每个变体要单独配图配文
- **C（物品等级）** ✅：一个条目 + 一个整数字段 → 内容量不变，纵向成长照旧；且 `itemLevel` 是纯整数，符合 Round 19"可量化的一律数值化"

#### 「境界提供基础数值与门槛（解锁秘境/底材）」释义（用户提问）

这句话（出自 `ADR-0005:2`）有**两个独立含义**：

1. **基础数值**：角色**裸装**时的强度来自境界。不穿装备，境界 5 也比境界 1 强；装备是在此基础上做乘法。
2. **解锁门槛（gating）**：境界决定能接触哪些内容——

| 境界 | 可进秘境 | 可掉底材 |
|---|---|---|
| 不入流 | 黑石矿 | 粗铁剑、布衣 |
| 二流 | 黑石矿、竹林 | 精钢剑、皮甲 |
| 绝顶 | 全部 | 玄铁剑、软猬甲 |

⚠️ **两个维度不要混**：
- **秘境层数** → 决定掉出来的装备**有多强**（itemLevel，深度）
- **境界** → 决定能进哪些秘境、哪些底材进入掉落池（gating，广度）

### 23.4 词缀标签化（Q53 相关，用户提问要求举例）

**反对：权重表**（每个底材列全部 20+ 条词缀权重，新增词缀要回头改所有底材，20 底材 × 60 词缀 = 1200 个数字）

**推荐：标签化**

```json
// 底材只声明偏好
{ "id": "base-heavy-sword", "preferredTags": ["力量", "破甲"] }

// 词缀自己带标签
{ "id": "affix-strength",    "tags": ["力量"] }
{ "id": "affix-armor-break", "tags": ["破甲"] }
{ "id": "affix-heavy-hit",   "tags": ["力量", "破甲"] }
{ "id": "affix-fire-damage", "tags": ["火系"] }
```

**权重计算**（建议 `权重 = 基础 × (1 + 匹配标签数 × 加成)`，加成 1.0）：

| 词缀 | 标签 | 匹配数 | 重剑掉落时权重 |
|---|---|---|---|
| 力量 +X | 力量 | 1 | 10 × 2 = 20 |
| 破甲 +X% | 破甲 | 1 | 10 × 2 = 20 |
| 重击 +X% | 力量+破甲 | 2 | 10 × 3 = **30** |
| 火系伤害 +X% | 火系 | 0 | 10 × 1 = 10 |

**好处**：新增词缀带 `tags:["力量"]` 即自动被所有偏好"力量"的底材青睐，**零改动**。这兑现 `ADR-0008:15`「标签化优先于类型化」。

⚠️ **需定细节**：多标签匹配时权重叠加方式。建议 `基础 × (1 + 匹配数 × 加成)`（温和，不出现 ×9 失控值），而非相乘。

### 23.5 特色词缀 = 机制改变型（Q54，用户按推荐采纳）

`ADR-0005:1` 规定绝世（5~6 词缀）含一条特色词缀。三种理解：

- A. 底材专属词缀（每类底材独一无二）
- B. 稀有强力词缀（独立小池，仅绝世可抽）
- **C. 机制改变型词缀** ✅ ——不是数值，而是改变机制（如"你的中毒会传染"）

选 C 的**额外价值**：这就是**兽的"机制放大器"模型的复用**——同一套 `condition + primitive` 表达，引擎零新增。且让绝世装备的区别是**玩法**而非数值，呼应"流派靠机制涌现"的整体思路。

### 23.6 洗练上限（用户判断，助手补充折中）

**用户判断**："决定上限的应该是那些最稀有的词缀，而那些装备是不会在低层掉落的"——逻辑成立。洗练只改数值不改词缀，低层掉不出 T3，故低层装备天花板天然就低，**不需要额外设上限**。

**助手补充的后果**：若数值**只由 tier 决定**，则第 30 层的 T3 与第 80 层的 T3 一样强，玩家刷齐 T3 满值即**数值毕业**。这意味着数值成长有终点，长期追求只能靠换构筑。

➡️ **折中建议（已采纳）**：**MVP 按用户判断做（数值只由 tier 定）**，但保留 `itemLevel` 系数作为**乘数配置项**（默认 1.0 = 不生效）。将来若要开启后期数值成长，改一个系数即可，不动结构。

### 23.7 离线掉落 = 玩家可选（Q53，用户决策："丢给玩家自己选"）

设置项四选一：

| 选项 | 行为 | 适合 |
|---|---|---|
| **保留最好的 N 件，其余分解** | 按评分排序留 N 件 | 默认推荐 |
| 全部转为材料 | 离线只产材料 | 背包洁癖、专注洗练 |
| 打包成战利品箱 | 上线自己开 | 喜欢开箱 |
| 全部保留 | 不处理 | 硬核（背包会爆） |

**引擎很便宜**：共用"掉落生成 → 后处理"管线，区别只在后处理策略。配置项 `lootPostProcess: keepBest | allMaterials | lootBox | keepAll` + 参数 N。

**附带**：`keepBest` 需"装备评分"函数——与 A.13 被搁置的"强度聚合指标"是同一件事（计算对象是装备而非角色）。

### 23.8 掉落提示与结算展示（用户 Round 23 补充）

**用户原话**："击杀时入库指的是：掉落时有提示，但在结算时再次展示本次秘境的全部掉落，并按品阶稀有度排序。"

| 时机 | 行为 | 作用 |
|---|---|---|
| 击杀瞬间 | 浮动提示 | 即时爽感 |
| 探索结算 | 汇总列表，按品阶/稀有度排序 | 不遗漏 + 仪式感 |

**边界（需定）**：探索**中断**（死亡/中途退出）时结算汇总还展不展示？
➡️ 建议：掉落记录只在**当前探索会话内存活**，会话结束（通关或中断）时展示一次；玩家强退则不展示。**数据已在背包不会丢，只是看不到汇总**——这样不需要为掉落日志增加存档字段。

### 23.9 Q55：词缀池存放形态（用户按推荐采纳）

**词阶不建独立条目**，而是"**20+ 个词缀条目，每个条目内含 3 阶数值表**"→ 20+ 个文件而非 60+ 个，且同一词缀的三阶放在一起便于调平衡。这是对 `content.md:30`「每条目一文件」的一个**有意的例外**。
