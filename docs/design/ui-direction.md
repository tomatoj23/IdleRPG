> **状态**：设计方向记录，**不是 ADR**。原因：①UI 不是 MVP 阻塞需求；②界面仍需深化（图标形式、日志密度、移动端主区高度分配等未定）。待方向收敛、进入实现阶段时再升级为 ADR。

## 一、视觉基准

**风格**：清新淡雅水墨，略带纸纹质感，写实非卡通，**武侠而非仙侠**（禁飞剑、金光、符箓、云海仙境、渡劫雷电）。

## 二、布局骨架

**桌面（16:9）**：三段式——左侧竖栏导航 + 顶部常驻资源栏 + 主内容区。主内容区二选一：**卡片网格**（Melvor，并列可选项：秘境、药材）或**行瀑布**（AD，层级生产链：炼丹）。

**移动端（9:16）**：顶部精简资源栏 + 底部 5 格标签栏（修/丹/秘/奇/设）+ 单列纵向堆叠；主行动按钮固定在底部标签栏上方通栏（拇指区）。

**通用**：导航 5 项且当前项高亮；每屏有且仅有一个主行动按钮。

## 三、各屏要点

| 屏 | 桌面 | 移动端 | 关键元素 |
|---|---|---|---|
| 主界面·修炼 | 环上 6 境界刻度的大进度环 + 朱印"闭关" + 右栏修炼日志 | 氛围主视图 + 居中进度环 + 日志 + 通栏"闭关" | **修为进度是一级视觉公民**；日志用时辰制（xkx100 语料） |
| 对峙战斗 | 左我右敌 + 中央招式名/伤害飘字/命中类型 + 底部通栏日志 | 敌上我下 + 中央动作区 + 可折叠日志 | 玩家挂机后回来只看结论 → **日志须支持折叠为仅结论** |
| 秘境列表 | 3×2 卡片网格 | 单列卡片（底部露出一角表示可滚） | 每卡：小景 + 秘境名 + 层数 + 推荐境界；未解锁置灰+锁章 |
| 角色养成 | 立绘 + 环绕 6 六边形装备槽 + 右侧招式/心法双栏 | 立绘+装备槽在上，招式/心法堆叠在下 | 装配槽与品阶可视化；底部标签汇总（剑法+2 毒系+1） |
| 炼丹 | 药材/丹方/丹炉三段行瀑布 | 同结构单列铺满 | 状态区分"可炼 / 未解锁"；右侧增益倒计时 |
| 奇遇弹窗 | 横幅弹窗（60%×45%） | 竖向弹窗（85%×40%） | 叙事文案 3~4 行 + 双选项小按钮 |

## 四、调研带来的可执行结论

1. **进度可视化三层次**（一念逍遥）：数值进度条（修为）+ 环境反馈（场景元素随境界增亮）+ 具象演进（境界突破时口诀文字浮现）
2. **渐进化解锁 UI**（AD/LBR/NGU）：元素随进度逐步出现，初期极简，避免一次性淹没
3. **装饰必须克制**（太吾绘卷反面教材）：面板质感（卷轴/竹简/印章）承担叙事，不额外堆装饰
4. **游戏内分类 = 玩家心智模型**（Melvor 与 Wiki 同构）：导航分类应与 `content/` 注册表结构对齐
5. **战斗文本直接可用 xkx100 语料**：四字格招式名、`$N 使出 $w，伤敌 $d` 模板、伤害类型×档位矩阵

## 五、待定项（深化时解决）

- 图标形式：单字方章 vs 图形图标（基准图用方章，但需确认是否能规模化）
- 战斗日志密度：桌面 2 行 / 移动 2 行是否够；折叠态显示什么
- 移动端主区高度分配（氛围视图 vs 信息区的比例）
- 是否需要暗色主题
- 立绘与头像的美术获取方式（后期 AI 生成 / 手绘 / 占位符）
