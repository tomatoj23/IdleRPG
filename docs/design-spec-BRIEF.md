## 1. 架构总则

### 1.1 分层

```
引擎层（core，零题材词汇）
  └─ mechanism primitive 注册表

内容层（content/）
  ├─ config/elements.json              七系
  ├─ config/element-combinations.json  稀疏有序组合表
  ├─ config/effect-params.json         primitive 参数 schema
  ├─ config/displayTiers.json          显示档位 50 档区间映射
  └─ effects/*.json                    效果 = primitive 组合 + 参数
```

引擎只读 `components[].primitive` 与 `params`，**永不读 `displayName`**。

```json
{
  "id": "eff-burn",
  "displayName": "灼烧",
  "textKey": "burn",
  "components": [
    { "primitive": "damage-over-time",
      "params": { "ticks": 3, "perTick": 12, "element": "fire", "tickTiming": "turn-start" } },
    { "primitive": "visual-flag", "params": { "flag": "burning" } }
  ],
  "stacking": { "mode": "refresh", "maxStacks": 1 },
  "dispel": { "dispellable": true, "resistance": 0 },
  "expiry": { "mode": "turns", "value": 3, "onDeath": "clear" }
}
```

### 1.2 primitive 全集（11 个）

| 类别 | primitive |
|---|---|
| **MVP 使用（9）** | `damage-over-time` `instant-damage` `stat-modifier` `rate-modifier` `crit-modifier` `dodge-modifier` `visual-flag` `heal` `dispel` |
| **MVP 只注册不使用（2）** | `armor-modifier`（作用于外功防御） `action-lock` |

**参数统一结构**：`amount` / `duration` / `targetSelector` / `condition`。
**可编辑项全为数据**：ticks、dispellable、resistance、expiry、stacking、onDeath、`chance`。参数 schema 在 config，编辑器据此生成表单。

`instant-damage` 的四个用法共用一套代码：

| 用法 | target |
|---|---|
| 普通攻击 | 敌方 |
| 自伤（燃血） | 自身 |
| 反伤 | 攻击者 |
| 溅射 | 相邻目标 |

**扩展性**：加第 8 系／删系／加组合／加效果（用现有 primitive）= 只改 config；加全新伤害模式 = 注册新 primitive（只加模块，不改已有代码）。

### 1.3 数值化：数字 + UI 映射表

```
引擎 core  ──→  数字等级 (level: 3)
存档        ──→  数字等级 (level: 3)
UI 映射表   ──→  "高手"        ← 改词、增删档位只动这里
```

**四条约束**：
1. 序列定义为 `content/config/` 里的**数组**，引擎只遍历
2. 引擎代码**不出现序列长度字面量**（不能有 `for i in 0..6`）
3. 引擎与存档**只存数字等级**，武侠词是 UI 层映射
4. 数值→档位映射是**配置表**（`displayTiers`），非硬编码阈值

**唯一需迁移的例外**：改**等级上限**（如 6 级 → 4 级），越界存档要收敛，属 `ADR-0002` 迁移。

**映射表项 = 配置对象**（key 是数值，`label` 只是其中一个字段）：

```json
{
  "rarity": [
    { "level": 0, "label": "寻常", "affixCount": { "min": 0, "max": 0 }, "hasSpecialAffix": false },
    { "level": 1, "label": "精良", "affixCount": { "min": 1, "max": 2 }, "hasSpecialAffix": false },
    { "level": 2, "label": "罕见", "affixCount": { "min": 3, "max": 4 }, "hasSpecialAffix": false },
    { "level": 3, "label": "绝世", "affixCount": { "min": 5, "max": 6 }, "hasSpecialAffix": true }
  ]
}
```

引擎读对象字段，**永不读 `label` 判断**。校验器检查：区间无缝、无重叠、覆盖全值域、下游规则自洽（如稀有度递增时词条数下限不得递减）。

### 1.4 引擎绝不按枚举的具体值分支

| | 引擎行为 |
|---|---|
| ❌ | `if (element === "fire") { ... }` |
| ✅ | `apply(config.elements[elementId].modifiers)` |

分支条件数据化：

```json
{ "id": "external", "defenseStat": "armor" }
{ "id": "internal", "defenseStat": "innerDefense" }
```

**加/删不对称**：加成员安全（加 config 项）；删成员需校验器检查引用 + `ADR-0002` 迁移。

**必须 id 化的三类**：primitive 类型／内容条目（武功、装备、怪物、兽、门派、脉）／事件类型与命中类型。

### 1.5 形状 vs 逻辑 + 三条原则

| | **形状（shape）** | **逻辑（logic）** |
|---|---|---|
| 是什么 | 存档结构、抽象层次、扩展点、枚举契约 | 具体业务规则的实现代码 |
| 改了后果 | **动架构 + 数据迁移** | 只改一个函数／模块 |

1. **内容可以后补，形状不能**——凡"将来加功能需重写引擎"处，现在就把抽象做出来。
2. **名称与数量都是内容，引擎不得写死**——可以"有几层"，但改了数量不能崩。
3. **凡可能变化的业务规则，都留一个可替换的边界**（策略函数／配置表／钩子），使其永远是"逻辑"问题。

**已识别的可替换边界**：离线致死规则／离线掉落后处理／波次调度／目标选择／掉落链／学习武功条件／强度聚合函数。

## 3. 战斗系统

### 3.1 完整形态

| 层 | 进攻侧 | 防御侧 |
|---|---|---|
| **战斗形态** | **支持多目标（1vN）**，1v1 为特例 | `targetSelector` 支持 单体／全体／相邻／随机 N 个／除主目标外 |
| **作用方式** | 内功 / 外功（招式字段；怪物攻击也标） | **外功防御** / **内功防御** — 2 个属性 |
| **系别性质** | 七系（附加伤害 = 兵刃层 × 系别系数） | 怪物亲和度（config） + 效果抵抗（条件修饰符） |
| **伤害构成** | 兵刃层（恒有）+ 系别层（可有可无） | — |
| **减伤公式** | — | 百分比递减 `减伤 = 防御 / (防御 + K)`，K 在 config |
| **组合** | 主（武功/门派）× 辅（装备）→ 有序查表 | — |
| **资源** | 招式消耗内力 | 内力上限（境界 + 心法 + 装备） |
| **命中判定** | 闪避 → 命中（**不做招架/格挡**） | 闪避率基础 5-10%，上限约 40%，递减在 config |
| **出招意图** | **intent 源可插拔**（MVP 仅 `auto-source`） | — |

```
一次攻击的伤害 = 兵刃层（无属性，恒有，受外功防御减）
              + 系别层（附加的效果与伤害，可有可无）
```

附加伤害 = 兵刃层 × 系别系数（config 里 7 个数）。

### 3.2 伤害计算管线（12 阶段）

```
1.  基础值      base          招式/装备/境界的原始数值
2.  固定加成    +flat         "火系伤害 +50"
3.  百分比加成  +add%         "火系伤害 +15%"（同类相加）
4.  乘法加成    ×mult         "所有伤害 ×1.2"（异类相乘）
5.  暴击        crit          暴击率判定 + 暴伤倍数
6.  攻方修正    source        内功/外功各自走对应防御
7.  守方减免    defense       外功防御 / 内功防御（百分比递减）
8.  易伤/抗性   vuln/res      目标受伤加深、系别亲和度
9.  闪避判定    dodge         0 或 1
10. 最终值      final
11. 后续触发    post          反伤、吸血、溅射、兽的追加
12. 应用        apply         扣血 → 判定致死 → 触发致命保护
```

第 12 步含**应用前拦截点**。每个 modifier 声明自己作用于哪个阶段。

> `ADR-0005:6` 的"固定值 → 加法百分比 → 乘法区"是**修饰符聚合规则**，与上表的**伤害应用顺序**是两件事。

### 3.3 七系表

| 系 | 轴 | 主位效果 | 辅位修饰 | 内力性格 | MVP 形态 |
|---|---|---|---|---|---|
| 金 | 破防 | 裂伤（受伤加深）、破防 | 锐化：加深、转即时 | 耗内破防 | 纯数值 |
| 木 | 疫毒 | 中毒、传染 | 蔓延：扩散、叠加速 | 寄赖/吸内（**需代价**） | **真状态** |
| 水 | 滞缓 | 冰寒（降频）、治愈(v2) | 流转：范围化、传导 | 滋养：回复/上限 | 纯数值 |
| 火 | 燃爆 | 灼烧、爆裂（溅射） | 爆裂：溅射、转爆发 | 倾泻：高耗高爆发 | **真状态** |
| 土 | 守护 | 护体（减伤）、稳固(v2) | 沉滞：延时、固化 | 承载：上限/代偿减伤 | 纯数值 |
| 风 | 迅疾 | 疾（提频）、连击(v2)、闪(v2) | 迅发：提速、连击化 | 轻灵：消耗降低 | 纯数值 |
| 雷 | 霆爆 | 暴（暴击）、震(v2)、瞬(v2) | 震荡：触发式、追加 | 激荡/背水（**需代价**） | 纯数值 |

**相克不做"削弱"，做"变异"**。七根轴：破防／疫毒／滞缓／燃爆／守护／迅疾／霆爆。恰好 **2 真状态 + 5 纯数值**。

**Round 3 三处调整**：金「流血」→「裂伤」；木「缠绕」→「传染」（频率轴让给水与风）；土的稳固／水的治愈／风的连击闪／雷的震瞬留 v2。

### 3.4 主辅有序组合

> **主属性（武功/门派）决定这一招"是什么"**——提供该系核心效果。
> **辅属性（装备）决定这一招"额外怎么样"**——对核心效果施加修饰。

组合表**有序**（水火 ≠ 火水），同系 7 格除外。表是**稀疏**的，未定义组合走各系默认修饰。

### 3.5 内功 / 外功

- 内功/外功 = 作用的**方式**；七系 = 伤害的**性质**。是 **2×8 矩阵**（8 = 七系 + 无属性）。
- **外功防御** / **内功防御** 两个属性。⚠️ 防御属性的旧名「护甲」已废弃，一律称「外功防御」。
- **内力与内功防御不硬挂钩**（避免堆内力成唯一解）；联动走内容层词缀。

### 3.6 防御侧

**不设玩家侧分系抗性。** 防御 = 外功防御 + 内功防御 + 怪物亲和度 + 效果抵抗。

```
monster: { id: "mon-fire-toad", affinities: { fire: -50, water: +30 } }
dungeon: { id: "dun-blaze-cavern", affinities: { fire: -30 } }
```

| 方向 | 进攻方 | 防守方 |
|---|---|---|
| 玩家 → 怪物 | 系别层伤害 | 怪物**亲和度**（config） |
| 怪物 → 玩家 | 系别层伤害 | 玩家**抗性**（条件修饰符） |

**玩家抗性 = 条件修饰符，不是属性**（角色 schema 0 字段，存档 0 数据）：

```
词缀「耐火」= stat-modifier {
  target: damage-taken,
  condition: { source: { element: "fire" } },
  amount: -20, unit: "percent"
}
```

**代价**：7 条词缀线是硬成本；抗性需上限 `-75%`（走乘法区递减）；UI 需额外做聚合读数。

**亲和度可按内容量线性铺开**（只给 Boss 和特色怪设，普通怪为 0）。

### 3.7 效果抵抗

```
减伤层：外功伤害 → 外功防御减        内功伤害 → 内功防御减
效果层：火系 → 灼烧              抵抗「抗灼」→ 不被点燃 / 持续时间减半
```

### 3.8 闪避

- 命中判定两级：闪避 → 命中。**不做招架/格挡**（留 v2）。
- 基础 5-10%，上限约 40%，递减 `实际闪避 = 闪避 / (闪避 + K)`（与外功防御、抗性同族公式），K 在 config。
- **只让这一次攻击落空，不跳过回合**。
- **是纯数值，不是状态**。
- 离线：期望值 `有效输出 = 原始输出 × (1 − 闪避率)`。
- **不绑定风系**：风系只通过内容层词缀权重更容易出闪避词缀，引擎不知情。
- **降低闪避**：`dodge-modifier` 对目标施加负值。土（压）／木（缠，走传染线）／水（滞）。

**硬约束**：① 上限与递减必须有（50% 闪避 = 生存时间翻倍，75% = 四倍）；② 不跳过回合；③ 纯数值。

**木不为减闪避恢复「缠绕」**（会重新引入已消掉的重叠）。

### 3.9 内力

**模型 A：持续回复**。战斗中按秒回内力；离线用**稳态 DPS 公式**（收支平衡点），**O(1)** 结算。

- **内力耗尽** → 自动切换**零消耗基础攻击**（用当前兵器普通攻击），输出下降但不归零。
- **上限来源**：境界 + 心法 + 装备词缀，走 ADR-0005 管线，引擎不写死公式。
- **MVP 只进最小形态**（上限 + 消耗 + 持续回复 + 零消耗基础攻击），七系差异化留 v2。

**七系 × 内力映射**：

| 系 | 内力性格 |
|---|---|
| 金 | 耗内破防：消耗额外内力换取无视部分外功防御 |
| 木 | 持续寄赖：中毒需持续供内力维持，或转为**吸内** |
| 水 | 滋养：内力回复加快 / 上限提高 |
| 火 | 倾泻：高消耗换高瞬时爆发，容易见底 |
| 土 | 承载：上限提高 / 受击时内力代偿减伤 |
| 风 | 轻灵：消耗降低 / 出手频率提高 |
| 雷 | 激荡：消耗换暴击；或**内力越低伤害越高**（背水） |

### 3.10 代价设计

**木系 · 吸内（四重代价）**：

| 代价 | 机制 |
|---|---|
| 不能吸干 | 目标内力不低于上限 25% |
| 转化效率低 | 吸 100 点只进账 40% |
| 自身伤害低 | 携带吸内的招式伤害系数 ×0.7 |
| 可被抵抗 | 走效果抵抗（「固本」类词缀） |

**雷系 · 背水**：

```
触发：内力 < 30%
加成：伤害 ×(1 + 最大加成 × 衰减系数)，最大加成 +50%（config）
```

| 代价 | 机制 |
|---|---|
| 门户大开 | 外功防御同步下降（伤害 +50% 时防御约 −25%） |
| 闪避降低 | 按同比例下降 |
| 需要主动维持 | 内力自动回复，维持低内力须持续消耗 |

**自伤换增益**（不绑定系别）：

| 代价 | 机制 |
|---|---|
| 无视外功防御 | 不走防御计算 |
| 无视护体 | `stat-modifier` 减伤无效 |
| 可致死 | 自伤能把自己打死 |
| 触发濒死档 | 自伤后的剩余生命档进入文本选择 |

**原则**：代价不是"数值打折"，是"在另一个维度上付账"。全部参数在 config，引擎零写死，**数值后置**（现在是初值不是承诺）。

### 3.11 出招与 intent

**加权轮盘**：`权重 = 基础权重 × 所有命中的调制器`

**MVP 4 个调制器**：冷却（冷却中归零）／内力（不足降权或归零）／重复衰减（刚放过临时降权）／系别亲和（同系升权）。
**留 v2**：条件加成、连携表。

**MVP 一个招式 = 一个条目，不做多形态**；丰富度靠**一个招式配多条文本变体，随机抽**。

```
战斗循环（core）：收集 intent → 校验 → 执行 → 推进时间
intent 来源（可插拔）：
  ├─ auto-source：加权轮盘        ← MVP 唯一
  └─ manual-source：玩家输入队列   ← 未来注册即可，core 零改动
```

**intent 三维度可独立配置**：

```
intent = { actor: 谁释放, skill: 用什么招, target: 对谁 }
        ← 各维度可 auto 或 manual
```

| 形态 | skill | target |
|---|---|---|
| 纯自动 | auto | auto |
| **半自动** | auto | **manual** |
| 全自动 | manual | manual |

**不在 schema 加 `activation` 字段**（为不确定功能预留数据字段违反 `ADR-0004:7`）；架构抽象现在就做，将来加字段由 `ADR-0002` 迁移承担。

**`targetSelector` 三来源，优先级 ③ > ② > ①**：① 招式自带（内容声明）；② 玩家策略配置（存档，**离线用此**）；③ 实时点击（仅在线）。

### 3.12 时间、随机、离线

- 战斗是**实时推进（tick）**，非回合制。冷却、DoT 跳数、状态持续都挂 tick。离线 = tick 快进 + 稳态公式。
- **随机源**：出招权重、暴击、闪避、词缀 roll、掉落、文本选择、兽出场、致命保护。
- 统一策略：**在线掷骰、离线期望值**。**致命保护是例外**（0/1 事件，期望值失真）。
- **离线致死 = A：离线战斗不致死**（封装为策略函数，后期可换）。

## 4. 战斗文本

### 4.1 槽位全集（13 个 + 闪避专用 4 个）

**语法 = `{attacker}` 英文花括号**，非 xkx 的 `$N/$n/$w/$l`。
**已删**：`{动词}`（应作模板固定文本）、xkx 代词 `$P/$p`（视角是集合级常量）。

`{attacker}` `{defender}` `{move}` `{weapon}` `{defenderWeapon}` `{limb}` `{damage}` `{consequence}` `{elementFlavor}` / `{opening}` `{moveIntro}` `{weaponAction}` `{verb}`

- `{elementFlavor}` 无属性时填**中性词，不可为空串**（否则产生"，，"）。
- ❓ 前 9 与后 4 是否分两类描述，见 §12.2。

### 4.2 模板 = 片段序列

```
{opening}{attacker}{moveIntro}「{move}」，{weaponAction}{elementFlavor}，
{weapon}{verb}{defender}的{limb}，{consequence}。
```

| 片段 | 词库示例 | 选择依据 |
|---|---|---|
| `{opening}` 起势 | ""、身形一晃、沉肩坠肘、脚下步法一变、深吸一口气 | 节奏档 |
| `{moveIntro}` 招式引出 | 使出一招／一招／倏然施出／缓缓递出／猛地挥出 | 品阶 + 节奏档 |
| `{weaponAction}` 兵器动作 | ""、剑身剧震、剑光急速穿梭、在半空折返划出一道弧光、剑锋嗡鸣 | 品阶 × 暴击 |
| `{elementFlavor}` 系别意象 | 剑锋赤红，热浪逼人／周身腾起一层赤焰／空气被灼得微微扭曲 | 系别（无属性填中性词） |
| `{verb}` 动词 | 直取／点向／刺向／抹向（剑·刺击类） | **兵器类型** |
| `{limb}` 部位 | 咽喉／后心／胸口（致命）· 左臂／右腿（非致命） | **致命度门控** + 与动词搭配 |
| `{consequence}` 后果 | 剑锋及体，皮肉焦黑／一股焦臭随之腾起／伤口边缘瞬间烙成黑褐色 | 伤害档 × 剩余生命档 × 作用方式 × motion × 系别 |

**片段序列可变长度**（模板自己声明 `segments` 数组）：下乘 3 段、绝学 7 段。

引擎只需"**带约束的词库抽取器**"：给定过滤条件，从池中随机取一条。

**生成示例**（同一招「白虹贯日」）：

> **重击·致命档**：身形一晃，你一招「白虹贯日」倏然施出，剑光急速穿梭，周身腾起一层赤焰，长剑点向黑衣人的后心，伤口边缘瞬间烙成黑褐色。
> **中等·火系**：你使出一招「白虹贯日」，剑锋嗡鸣，剑锋赤红，热浪逼人，长剑直取黑衣人的胸口，剑锋及体，皮肉焦黑。
> **轻伤·火系**：沉肩坠肘，你缓缓递出「白虹贯日」，长剑抹向黑衣人的左臂，剑锋掠过，衣袖裂开一道口子，血线缓缓渗出。

### 4.3 三层门控

**① 致命度门控**

```
致命部位（咽喉／后心／胸口／头顶）仅当：
    伤害档 ∈ {重, 濒死}  AND  剩余生命档 ∈ {少, 危}
否则只抽非致命部位（四肢／肩臂／腰肋）
剩余生命档 = 危 且伤害档 = 濒死 → 启用「致命一击」专属词库
```

**② 搭配约束**（兵器 → 动词池 → 部位白名单）

```json
{ "id": "直取", "motion": "thrust", "limbs": ["咽喉", "胸口", "后心", "小腹"] }
{ "id": "扫向", "motion": "sweep", "limbs": ["腰间", "脖颈", "左腿", "右腿"] }
{ "id": "劈落", "motion": "chop",  "limbs": ["头顶", "左肩", "右肩"] }
```

兵器类型决定动词池：剑→刺/点/撩/抹/扫/劈，刀→劈/砍/斩/削，棍→扫/砸/抡/戳，拳掌→拍/击/推/按。

**③ 节奏一致性**：先定整体节奏档（急／缓／稳，由招式特性与是否暴击定），各片段只从同档池抽。

| 字段 | 状态 | 说明 |
|---|---|---|
| `damage` | 已有 | 伤害数值 |
| `damageRatio` | 已有 | 轻/中/重/濒死 四档 |

### 4.5 闪避文本（独立模板族）

```
{dodgeSubject}{dodgeManner}，{dodgeMove}避过{attacker}的「{move}」{dodgeAftermath}。
```

| 片段 | 选择依据 |
|---|---|
| `{dodgeSubject}` | 闪避方（在闪避文本里是主语） |
| `{dodgeManner}` | 剩余生命档 × 是否有身法 × 实力差 |
| `{dodgeMove}` | 身法招式名（可为空） |
| `{dodgeAftermath}` | **险胜档**专用（按闪避判定值与阈值的差距分档，不需新字段） |

**实力差门控**（防"大师险胜新手"）：

| 双方显示档位差 | 闪避成功的叙事性质 |
|---|---|
| 攻击方远高于防守方 | **侥幸** |
| 双方接近 | **正常** |
| 防守方远高于攻击方 | **从容** |

随机性保留在档位内部（每档 3-5 条候选）。

> 闪避文本中主语是防方，但 `{attacker}`/`{defender}` 的语义角色不变，只是叙述视角转到防方。

### 4.6 兽文本

- **触发条件 = 兽正在执行它的机制**（不是随机乱入）。
- **频率节流**：按概率出场（config，如 25%）+ 出场冷却（如 3 回合内不重复）。
- **品阶差异 = 片段数**：下乘 1 段／中乘 2 段／绝学 3-4 段。
- **与主人互动四种**：救援（主人受致命档伤害）／配合（出招时同步）／**反馈**（主人血量档变化）／增益。

"反馈"型与 `{opening}` 残血词库天然联动——主人残血时 `{opening}` 说"虽已浑身是血，仍作殊死一搏"，兽的反馈紧随其后。

- **架构要求**：可选插入片段。只需 `beastTrigger` + 文本组合器支持"主模板 + 可选插入"。
- **并发**：兽片段插在主文本**之前**（因果上先发生）。

## 5. 兽（驭兽）

### 5.1 定位：本质是装备，不是战斗单位

兽 = **一组修饰符 + 一段可声明的叙事片段**。引擎不需要认识"兽"，只知道"带 narrative 的装备"。

| 兽 | 效果 | 修饰维度 |
|---|---|---|
| 毒蜂（木） | 扩散中毒 | `targetSelector`（单体 → 多个） |
| 火鸦（火） | 引爆灼烧 | trigger + `condition` |
| 寒蟾（水） | 延长迟缓 | `duration` |
| 铁啄鹰（金） | 维持破防 | `duration`（不衰减） |
| 石龟（土） | 转移伤害 | `stat-modifier` 减伤 + 叙事包装 |
| 灵隼（风） | 缩短冷却 | `rate-modifier` |
| 雷兽（雷） | 暴击追加 | `condition: on-crit` + `instant-damage` |

**边界**：兽不能 ① 成为敌人攻击目标；② 有血量、会死；③ 在主人不出招时独立行动。石龟"替你挡下"实为**减伤修饰符 + 叙事包装**。

**槽位**：独立"随从"栏，不占 7 个装备槽。

**形态**：驭兽（真实动物）。机关傀儡留待门派设计时评估；召唤物排除（`ui-direction.md:9` 已禁符箓）。

### 5.2 机制放大器（不是伤害复制品）

兽**不造成该系伤害，它改造该系机制的行为方式**。七个都是"改变主角已有机制的某个参数"。

### 5.3 获取与 MVP

**获取**：门派贡献兑换 + 随境界自动成长（避免第二个养成循环）。喂养/进化留 v2。（ADR-0008 不做任务体系，"任务奖励"途径排除。）

**MVP = 2 只**：木系毒蜂（进攻型）+ 土系石龟（防御型）。其余五系待模型验证后补（届时加兽是纯内容）。

|---|---|---|
| 致命判定 | "应用伤害之前"的**拦截点** | 形状清单 #8 |

## 6. 门派

### 6.1 三件套与脉

门派 = **武功池 + 缺省系别 + 生产加成**（外加贡献货币、脉、师父）。

**脉（`lineageId`）是武功池的细分标签，不是玩家的身份选择**：

| | 脉（采用） | 专精（避免） |
|---|---|---|
| 是什么 | 武功池的**归类标签** | 玩家的**身份选择** |
| 能否同时拥有多个 | **能**（受贡献/前置限制） | 不能（互斥） |
| 谁来"选" | 玩家通过**装配**选（招式 4 / 心法 3 槽位限制） | 系统让玩家进入时选死 |

实现：`content.md:42` 已有 `sectId`，脉用并行字段 `lineageId`，校验器照 `sectId` 做覆盖与连通检查。

### 6.2 门派节奏差异

| 门派 | 缺省系 | 节奏 | 内力特性 |
|---|---|---|---|
| 丐帮 | 火 / 雷 | **爆发型**：短时间倾泻，之后疲软 | 高消耗、高回复需求 |
| 武当 | 水 / 土 | **持久型**：防守反击，拖得住 | 低消耗、续航强 |
| 唐门 | 木 / 金 | **累积型**：毒/破防叠加，越打越疼 | 中等消耗、前置投入长 |

### 6.3 五条必须现在留的引擎预留

1. **门派内进阶是运行时进度，进存档**
2. **已学武功必须与当前门派解耦（最关键）**——已学武功是玩家的属性，门派只是获取来源
3. **condition 匹配维度可扩展**（见 §11.1）
4. **门派间关系是一张内容表**（正派/魔教、同盟/敌对将来会变），引擎只查表
5. **门派归属是运行时状态、可变更**（存档存"当前门派"字段）

> 其余 14 项机制（生产加成、门派贡献、门派专属装备/词缀/兽/秘境、被动加成、竞技排行等）均无需预留——归属标签、已有 modifier 或内容配置即可。

### 6.4 入门条件与师父

- **入门条件** → **MVP 条件恒真**，但"学习武功"流程带条件检查点（形状清单 #13）
- **师父（`sect.masters`）** → **先只留字段**，无实际内容

## 8. 秘境

### 8.1 层内模型 = 定时波次

```
触发下一波 = 时间到  OR  上一波已清空     ← 取较早者

进入第 N 层
  ├─ t=0        生成第 1 波
  ├─ t=T1 或 第1波清空（取先到）→ 生成第 2 波
  ├─ ...
  └─ 场上清空 且 波次已全部生成 → 通关本层
```

难度是**涌现**的（清怪速度 vs 生成速度的比值），不是配出来的。

### 8.2 四参数（全在 `content/config/`）

| 参数 | 说明 |
|---|---|
| `waveCount` | 本层几波 |
| `waveInterval` | 波间隔（固定值／区间随机／逐波递减） |
| `waveComposition` | 每波什么怪（固定表／从池随机） |
| `maxConcurrent` | 场上怪物上限（**技术护栏 12–20，非难度调节**；超出延后而非丢弃） |

**随机化两层**：间隔 `T ± 20%`；构成本层池随机 + 保底固定。**精英/Boss 不进随机池**。
**原则：随机性放在节奏与搭配上，不放在难度上。**

### 8.3 层主、解锁、层 modifier

- **层主**：每 N 层一个（如第 5、10 层），非每层都有
- **解锁**：混合式——前几个链式引导，之后按推荐境界并列开放
- **推荐境界** = **软提示**，非硬门槛；硬门槛只用于"未通关前一层"
- **层可带 modifier**（如"此层火系伤害 +30%"），与怪物亲和度同族，复用同一套
- **计时器「一炷香」不实现** → 无探索时长/门票系统
- **MVP 3 个秘境**

### 8.4 离线推进

```
单波清怪时间 ≈ 波总HP / 稳态DPS
本层耗时     ≈ Σ清怪 + Σ间隔
离线可推进层数 = 离线时长 / 平均单层耗时
```

推进会在卡住的层停下。

### 8.5 掉落时机与展示

**掉落时机 = 击杀时即时入库**（非探索结束统一结算）。

| 时机 | 行为 |
|---|---|
| 击杀瞬间 | 浮动提示 |
| 探索结算 | 汇总列表，按品阶/稀有度排序 |

掉落记录只在**当前探索会话内存活**——会话结束（通关或中断）时展示一次，强退不展示（数据已在背包，不需为掉落日志增存档字段）。

## 9. 装备

### 9.1 底材 = 分层

**每个底材是独立条目，声明自己的层数区间与品阶范围**。高层掉的是**另一个底材**（换名字/描述/美术），而非同一条目加 `itemLevel`。

```
底材条目（每个独立）：
  ├─ 名字 / 描述 / 美术    ← 各自不同
  ├─ 槽位
  ├─ 固有词缀
  ├─ 偏好标签
  ├─ 层数区间（哪个层数段会掉落）
  └─ 品阶范围（能出哪些阶位的词缀）
```

- **`itemLevel` MVP 不启用**，降级为可选乘数（默认 1.0）。
- 美术侧：`ADR-0003:8` 的"资产按约定路径引用（`assets/icons/<集合>/<id>.png`）"天然支持每底材一 id 一图标。

### 9.2 掉落链（可配置管线，不能写死）

```
击杀
 ├─ ① 掉不掉（roll）
 ├─ ② 按秘境层数筛选可用的底材池
 ├─ ③ 从池中选一个底材
 ├─ ④ 掷稀有度                    ← 因
 ├─ ⑤ 按稀有度定词缀条数            ← 果
 ├─ ⑥ 抽词缀（受底材偏好标签影响）
 ├─ ⑦ 每条词缀掷阶位（受【底材声明的品阶范围】限制）
 └─ ⑧ 附加底材的固有词缀（固定，非随机）
```

**稀有度是因，词条数是果**——先定稀有度，再按稀有度生成词条。

### 9.3 词缀倾向 = 标签化

```json
// 底材只声明偏好
{ "id": "base-heavy-sword", "preferredTags": ["力量", "破防"] }

// 词缀自己带标签
{ "id": "affix-strength",    "tags": ["力量"] }
{ "id": "affix-armor-break", "tags": ["破防"] }
{ "id": "affix-heavy-hit",   "tags": ["力量", "破防"] }
{ "id": "affix-fire-damage", "tags": ["火系"] }
```

**权重 = 基础 × (1 + 匹配标签数 × 加成)**，加成 1.0。

| 词缀 | 匹配数 | 重剑掉落时权重 |
|---|---|---|
| 力量 +X | 1 | 10 × 2 = 20 |
| 破防 +X% | 1 | 10 × 2 = 20 |
| 重击 +X% | 2 | 10 × 3 = **30** |
| 火系伤害 +X% | 0 | 10 × 1 = 10 |

新增词缀带 `tags` 即自动被所有偏好该标签的底材青睐，**零改动**（兑现 `ADR-0008:15`）。多标签用**温和叠加**而非相乘（避免 ×9 失控）。

### 9.4 特色词缀 = 机制改变型

绝世（5~6 词缀）含一条特色词缀：**不是数值，是改变机制**（如"你的中毒会传染"）。复用兽的 `condition + primitive` 表达，引擎零新增。

### 9.5 洗练上限

**MVP：数值只由 tier 决定**（低层掉不出 T3，天花板天然受限）。底材声明的品阶范围**在数据上锁死天花板**，洗练再多次也出不了 T5。

保留 `itemLevel` 系数作乘数配置（默认 1.0），将来开启后期数值成长时改一个系数即可。

### 9.6 离线掉落 = 玩家可选

配置 `lootPostProcess: keepBest | allMaterials | lootBox | keepAll` + 参数 N。

| 选项 | 行为 |
|---|---|
| **keepBest**（默认） | 按评分排序留最好的 N 件，其余分解 |
| allMaterials | 全部转为材料 |
| lootBox | 打包成战利品箱，上线自己开 |
| keepAll | 不处理 |

共用"掉落生成 → 后处理"管线，区别只在后处理策略。

### 9.7 词缀池与底材规模

- **词缀池**：20+ 个词缀条目，**每个内含 3 阶数值表**（对 `content.md:109`「每条目一文件」的有意例外）。
- **MVP 底材 = 42 个**（7 槽位 × 3 层级段 × 2 变体），约 294 项内容。

| 配置 | 算式 | 条目数 |
|---|---|---|
| 精简版 | 7 × 3 × 1 | 21 |
| **MVP（宽松版）** ✅ | **7 × 3 × 2** | **42** |
| 完整版 | 7 × 5 × 2 | 70 |
| 完整版（多） | 7 × 5 × 3 | 105 |

- **槽位（7）**：兵器 / 冠 / 甲 / 腕 / 腰 / 裤 / 靴
- **层级段（3）**：秘境层数分段，如 1–5 / 6–15 / 16+
- **每段变体数（2）**：某段某槽位有几种底材可选

每个条目 7 样内容：名字、描述、`assets/icons/equipment/<id>.png`、固有词缀、偏好标签、层数区间、品阶范围。

⚠️ **两个维度不可混**：**秘境层数** → 装备有多强（深度）；**境界** → 能进哪些秘境/哪些底材入池（gating，广度）+ 提供裸装基础数值。

## 11. 引擎预留清单

### 11.1 `condition` 维度（必须可扩展）

```
element（系别）/ source（内功|外功）/ moveId（招式）/ moveTier（品阶）
targetState（目标状态）/ sectId（门派）/ lineageId（脉）/ equippedTag（装备标签）
/ equippedSet（套装）
```

只要 condition 可扩展，"强化特定技能"永远不用改引擎。

### 11.2 `targetSelector`

单体 ／ 全体 ／ 相邻 ／ 随机 N 个 ／ 除主目标外。
三来源优先级：实时点击 > 玩家策略配置（存档）> 招式自带（内容）。

### 11.3 武学效果穷举（16 项）

| # | 效果 | primitive |
|---|---|---|
| 1 | 造成伤害 | `instant-damage` |
| 2 | 持续伤害 | `damage-over-time` |
| 3 | 增益 / 减益 | `stat-modifier` |
| 4 | 控制 | `action-lock` |
| 5 | 破防 | `armor-modifier` |
| 6 | 闪避修正 | `dodge-modifier` |
| 7 | 频率修正 | `rate-modifier` |
| 8 | 暴击修正 | `crit-modifier` |
| 9 | 治疗 / 回复 | `heal` |
| 10 | 吸血 / 吸内 | `instant-damage` + `heal` |
| 11 | 反伤 | `instant-damage`（target=攻击者） |
| 12 | 溅射 | `instant-damage`（targetSelector=相邻） |
| 13 | 连击 | ⚠️ 需"重复执行"能力，待确认 |
| 14 | 驱散 | `dispel` |
| 15 | 护盾 | ⚠️ 可归入 `stat-modifier`，但有"吸收量"语义，可能需独立 |
| 16 | 位移 / 位置 | 未涉及（战斗是否有位置概念未定） |

### 11.4 装备影响穷举（12 项）

| # | 影响 | 状态 |
|---|---|---|
| 1 | 数值加成（攻/防/生命） | ✅ |
| 2 | 系别加成 | ✅ |
| 3 | 定向强化（某招式 +X%） | ✅（§7.3） |
| 4 | **机制改变**（"你的中毒会传染"） | ✅ 即兽的放大器模型，可推广 |
| 5 | 触发效果（当 X 时 Y） | ✅ trigger + condition |
| 6 | 内功/外功偏向 | ✅ `source` 维度 |
| 7 | **套装效果**（集齐 N 件） | ✅ 需 `equippedSet` 维度 |
| 8 | 负面词条 | ⚠️ modifier 支持负值，随时可加 |
| 9 | 装备特效（击杀回血） | ✅ |

| 11 | 洗练（重随单条词缀） | ✅（`CONTEXT.md:71`） |
| 12 | 升级 / 强化 | ⚠️ ADR-0005 未提，与 socket 同族 |

**1vN 支持，1v1 为特例**。连续战斗（层内波次）已覆盖。限时/生存、Boss 特殊机制、PvP 未涉及。
