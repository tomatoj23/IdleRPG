# 装备驱动的多 Build 系统（暗黑/POE 式刷宝）

用户明确要求《暗黑破坏神》《流放之路》式的装备驱动、多构筑玩法，取代初版"简单词缀"方案：

1. **掉落结构**：底材（每槽位多类，带固有词缀）× 稀有度（普通 0 词缀 / 魔法 1~2 / 稀有 3~4 / 传说 5~6 含特色词缀）× 词缀阶位（T1~T3，高阶仅高层数秘境掉落）。掉落等级由秘境层数决定。
2. **数值模型**：境界提供基础数值与门槛（解锁秘境/底材），强度主体来自装备词缀与心法的**修饰符聚合**。分层计算：固定值 → 加法百分比 → 乘法区。词缀、心法、增益丹统一产出修饰符，走同一条聚合管线（即 ADR-0004 的声明式效果系统）。
3. **Build 来源**：词缀与武功通过**标签联动**（词缀"剑法冷却 -15%" × 武功标签"剑法"）。换一套装备即换流派；MVP 不做武器 socket，数据结构预留。
4. **装备循环**：掉落 → 穿戴 + 分解（得材料）+ 洗练（材料重随单条词缀数值）。词缀重铸、底材打造等完整工艺留后续。

## Consequences

- 修饰符聚合引擎是核心基础设施，先于战斗系统实现；所有数值来源（词缀/心法/buff）禁止直接改属性，必须走修饰符。
- 词缀池内容量按"条数 × 阶位"扩张（MVP 20+ 条 × 3 阶），Schema 需支持阶位表。
- 武功标签、词缀标签是内容层字段，标签枚举也在 `content/config/` 中定义。
