# 引擎与内容完全分离

架构原则（用户明确要求的最高约束）：**代码是通用放置 RPG 引擎，武侠只是恰好装载的一套内容包**。规则：

1. **内容边界最大化**：不仅条目（武功/装备/怪物/丹方/秘境/门派/奇遇），连结构性配置也全部数据化——境界序列与曲线、离线收益上限、战斗间隔、品质与品阶定义、装配槽数量、突破材料曲线等，全部在 `content/config/`。
2. **引擎零内容**：引擎代码禁止出现题材词汇（"武侠""修为""闭关"等中文业务词只存在于内容层与 UI 文案）；禁止写死任何数量（门派数量 = `content/sect/` 文件数，境界 = `config/realms.json` 数组长度，引擎只遍历）。
3. **扩展留白**：效果系统采用声明式修饰符（stat/trigger 枚举池）而非硬编码逻辑，枚举池可扩充；数值模型、掉落规则等全部由 config 驱动，后期扩展新机制时只加枚举与规则槽，不动核心循环。

## Consequences

- 所有系统代码只能通过内容注册表（Content Registry）拿配置，直接 import 内容数据视为违规。
- UI 文案与业务术语归内容层管理，界面是"哑"的通用组件。
- 代价：初期开发比"写死在代码里"多一层间接（Schema、Registry、加载校验），属有意支付的成本。
